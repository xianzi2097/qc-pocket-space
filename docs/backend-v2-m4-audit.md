## 一、横切能力 11 项逐条对账

| # | V1 能力 | V2 现状 | 结论 |
|---|---------|---------|------|
| 1 | Token 鉴权（内存 `ACTIVE_TOKENS`，重启全失效） | `auth_sessions` **表**（D5）：过期时间、可注销、可踢下线、**重启不丢** | ✅ **更强** |
| 2 | 登录梯度限流（5→30s / 10→5min / 15→30min / 20→2h，按真实 IP） | `login_attempts` 表 + `check_login_allowed`（M0），**重启计数不丢**；ProxyHeaders 仅信 127.0.0.1 同款保留 | ✅ 存活且更强 |
| 3 | 路径穿越防护（`_safe_path` / `_valid_new_name`） | `app/files.py` 五类拦截（../·绝对路径·盘符·非法字符·超长）+ safe_join realpath 兜底；16 条参数化单测 | ✅ 存活 |
| 4 | 原子写 + 文件锁（`_file_lock` 手写防并发覆盖） | **整类需求消失**：结构化数据入库存事务（引擎保证原子/并发），文件只剩纯字节（M2 文件树）——V1 notes.py 忘加锁那类病无法再犯 | ✅ **被引擎取代** |
| 5 | 软删/回收站（V1 两套：用户 DB 版 + 内容文件版） | **D10 合一**：一张 `trash` 表 + `trash/` 磁盘目录，4 接口（list/restore/purge/clear），恢复按 type 三分支、账号永不彻底删 | ✅ 存活（M4① 落地） |
| 6 | 每日自动备份（`backup.py`：整 data 目录 zip、sqlite 快照、保留 14 份） | `app/backup.py` 平移：同策略；`v2_auto_` 前缀与 V1 包隔离（互不清理）；快照含 WAL；3 条验收单 | ✅ 存活（M4② 落地） |
| 7 | 启动自检（`self_check_user_dirs`：DB 有用户但目录缺失→补建） | **被双写事务取代**：V2 建行必建目录、失败回滚（M2 `create_asset`），不存在"库有盘无"的半状态路径；`ensure_dirs` 启动建骨架 | ✅ **被取代**（如真实部署出现孤儿再补巡检） |
| 8 | admin 种子账号（不存在则建 admin/111111 提示改密） | `main._ensure_admin` 同款 | ✅ 存活 |
| 9 | 统一信封（成功 `{"status":"success"}` / 失败 `{"detail"}`） | **完整信封** `{code,msg,data}` + 10 组错误码表 + 4 个错误处理器（M0）；msg 承载"可恢复/不可恢复"真相 | ✅ **升级** |
| 10 | 文件大小限制（课件 50MB / 头像 2MB） | `UPLOAD_MAX_BYTES=50MB` / `AVATAR_MAX_BYTES=5MB`（A8 拍板提到 5MB）；413+1113，磁盘满 507+9001 | ✅ 存活（头像按拍板放宽） |
