# 后端 V2 · 数据库表结构（逐字段）

> **真相源是 [backend_v2/app/models.py](../backend_v2/app/models.py)——本文件是它的说明书，改表必改这里。**
> 规则（D7）：上线前 schema 允许推翻；上线后只增不改。
> 配套阅读：[API 规范](./backend-v2-api-spec.md) §2（表）/ §3（接口）。

## 总览：14 张表

| #  | 表                  | 分组 | 一句话                                            | 阶段   |
| -- | ------------------- | ---- | ------------------------------------------------- | ------ |
| 1  | `accounts`        | 账号 | 账号本体，一切数据的中心                          | M1 ✅  |
| 2  | `auth_sessions`   | 账号 | 登录后签发的 token                                | M1 ✅  |
| 3  | `login_attempts`  | 账号 | 登录失败计数（防暴力破解）                        | M1 ✅  |
| 4  | `classes`         | 班级 | 班级本体                                          | M1b ✅ |
| 5  | `class_members`   | 班级 | 谁在哪个班（关系表）                              | M1b ✅ |
| 6  | `assets`          | 内容 | 资产合表：课程/书架/资料/软件（bucket 分类，D16） | M2 ✅  |
| 7  | `file_order`      | 内容 | 文件树自定义排序                                  | M2 ✅  |
| 8  | `message_folders` | 沟通 | 站内信文件夹                                      | M3 ✅  |
| 9  | `messages`        | 沟通 | 站内信                                            | M3 ✅  |
| 10 | `notebooks`       | 个人 | 笔记本                                            | M3 ✅  |
| 11 | `notes`           | 个人 | 笔记                                              | M3 ✅  |
| 12 | `class_records`   | 其他 | 课堂记录（同班同日覆盖）                          | M3 ✅  |
| 13 | `settings`        | 个人 | 每人的界面偏好                                    | M3 ✅  |
| 14 | `trash`           | 其他 | 统一回收站（软删快照）                            | M1 ✅  |

**关系网**（记住"每张表都指回主人"这一条规律即可）：

```
accounts（中心）
  ├─ class_members ──→ classes        谁在哪个班
  ├─ notebooks ──→ notes              谁的笔记本里有什么
  ├─ messages (sender/receiver)       谁发给谁（folder_id → message_folders）
  ├─ assets (owner_id)                谁的资产（课程/书架/资料/软件）
  ├─ settings                         谁的界面偏好
  └─ auth_sessions                    谁的登录态
trash ──→ 指向被软删的 account / class（payload 存恢复所需快照）
```

**通用约定**：

- **id**：`new_id()` 生成的 12 位随机串（字母表去掉了易混的 `l/o/0/1`），不从登录名推导——登录名可改，id 永不变
- **时间**：一律 `String(19)` 格式 `"YYYY-MM-DD HH:MM:SS"` 字符串，SQLite 里好排序好比较（例外：`accounts.enrolled_at` 只存 `YYYY-MM-DD` 日期）
- **JSON 列**：存 JSON 文本，Python 侧是 dict/list，读出来直接用
- **软删**：没有物理删除，状态位 + 回收站，数据可恢复
- **老库补列（2026-10-12）**：SQLite 的 `ADD COLUMN` 没有 `IF NOT EXISTS`，新列登记在 `db.py::_EXTRA_COLUMNS`，启动时 `init_db → _ensure_columns` 自动对老库补列；**加列容易、删列/改类型难（要重建表），字段想清楚再加**

## 1. `accounts` — 账号本体

谁是谁、能干什么，全平台唯一的身份真相。

| 字段              | 类型                   | 含义               | 取值 / 备注                                                     |
| ----------------- | ---------------------- | ------------------ | --------------------------------------------------------------- |
| `id`            | String(12) · 主键     | 账号唯一 id        | `new_id()` 生成；**永不改变**，文件路径、班级关系全挂它 |
| `username`      | String(64) · 唯一索引 | 登录名（账号名）   | 可改（学生不开放改）；重名 → 业务码 3001                       |
| `password_hash` | String(255)            | 密码哈希           | argon2 哈希，**永不明文**；重置密码 = 覆盖此列            |
| `role`          | String(16) · 索引     | 角色               | `admin` / `teacher` `student`；决定权限矩阵哪一行         |
| `avatar_path`   | String(255)            | 头像标记或文件路径 | 预设头像存标记`avatar_07`；自定义上传存磁盘路径               |
| `descriptors`   | Text（JSON 串）        | 学生完整备注资料   | V1 有此设计，学它（画像/标签/备注，学生管理阶段用）                |
| `status`        | String(16)             | 账号状态           | `active` 正常 / `deleted` 已停用（A6 软删）；停用后无法登录 |
| `created_at`    | String(19)             | 注册时间           | 创建时写入，不再变                                              |
| `remark`        | String(255)            | 备注（老师便签）   | 老师/管理员的简短便签（如"试听生"）；公开视图不返回（2026-10-12） |
| `enrolled_at`   | String(19)             | 入学/入职时间      | **一列两义**：学生=入学、老师=入职；`YYYY-MM-DD`，≠`created_at`（2026-10-12） |
| ~~`name`~~      | —（已移除）            | ~~姓名~~ **已移除** | 2026-10-11 曾加、2026-10-12 代码移除（旧库残留空列无害）；**显示名即账号名**（身份 = id + 账号名 + 密码） |

## 2. `auth_sessions` — 登录态

登录成功签发一行，请求带着 token 来，查这张表验明正身。

| 字段           | 类型               | 含义              | 取值 / 备注                                |
| -------------- | ------------------ | ----------------- | ------------------------------------------ |
| `token`      | String(64) · 主键 | 会话令牌          | 随机生成；前端登录后每次请求带上           |
| `account_id` | String(12) · 索引 | 属于谁            | →`accounts.id`                          |
| `ip`         | String(45)         | 登录时的客户端 IP | 45 位是 IPv6 上限；审计用                  |
| `user_agent` | String(255)        | 登录的浏览器/设备 | 审计用                                     |
| `created_at` | String(19)         | 登录时间          |                                            |
| `expires_at` | String(19) · 索引 | 过期时间          | 过期即失效；改密后全部会话失效也靠清这张表 |

## 3. `login_attempts` — 登录限流

按 IP 记失败次数，越错越难登（梯度限流），防机器人撞库。

| 字段             | 类型                   | 含义             | 取值 / 备注                       |
| ---------------- | ---------------------- | ---------------- | --------------------------------- |
| `id`           | Integer · 主键自增    | 行号             | 无业务含义                        |
| `ip`           | String(45) · 唯一索引 | 客户端 IP        | 一行一个 IP                       |
| `fail_count`   | Integer                | 连续失败次数     | 登录成功清零；到阈值触发锁定/延迟 |
| `last_fail_at` | String(19)             | 最近一次失败时间 | 用于"冷却 N 分钟后重置"的判断     |

## 4. `classes` — 班级本体

| 字段           | 类型               | 含义     | 取值 / 备注                                                    |
| -------------- | ------------------ | -------- | -------------------------------------------------------------- |
| `id`         | String(12) · 主键 | 班级 id  | `new_id()`；API 路径里的 `{classId}`                       |
| `owner_id`   | String(12) · 索引 | 班主任   | →`accounts.id`；权限第一道门：只有他（和 admin）能管这个班  |
| `name`       | String(64)         | 班名     | **重名按老师隔离**：张老师的"一班"和李老师的"一班"不冲突 |
| `schedule`   | JSON               | 每周排课 | 如`{"周一": "18:00-19:30"}`；学生没有个人课表时跟随它        |
| `created_at` | String(19)         | 建班时间 |                                                                |

唯一约束：`(owner_id, name)` 同一老师不能起两个同名班 → 业务码 40001。

## 5. `class_members` — 班内学生（关系表）

**学生移出班级 = 删这里一行；`accounts` 等其他表零改动。**

| 字段           | 类型                | 含义     | 取值 / 备注                                |
| -------------- | ------------------- | -------- | ------------------------------------------ |
| `id`         | Integer · 主键自增 | 行号     | 无业务含义                                 |
| `class_id`   | String(12) · 索引  | 哪个班   | →`classes.id`                           |
| `account_id` | String(12) · 索引  | 哪个学生 | →`accounts.id`；只允许 `role=student` |
| `joined_at`  | String(19)          | 入班时间 |                                            |

唯一约束：`(class_id, account_id)` 同班同人不能进两次 → 业务码 40009。

## 6. `assets` — 资产合表（D16）

**四类资产一张表**：课程、书架、资料、软件只是 `bucket` 值不同；`type/format/publish` 为课程族专用，资料/软件行保持为空。

| 字段            | 类型               | 含义                 | 取值 / 备注                                                                                  |
| --------------- | ------------------ | -------------------- | -------------------------------------------------------------------------------------------- |
| `id`          | String(12) · 主键 | 资产 id              | `new_id()`；文件树挂在它下面                                                               |
| `owner_id`    | String(12) · 索引 | 属于谁               | →`accounts.id`                                                                            |
| `bucket`      | String(16) · 索引 | **四分类**     | `courses` 课 / `books` 书 / `reference` 参考资料 / `download` 软件（D15 四选一落这） |
| `name`        | String(128)        | 资产名               | **同一 owner 下全局唯一**（跨类不重名）→ 业务码 5001/6001                             |
| `description` | Text               | 说明                 |                                                                                              |
| `tags`        | JSON（list）       | 标签                 | 筛选用                                                                                       |
| `type`        | String(32)         | 课程族：课程类型     | 默认空；`scratch` / `python` / `cpp`…                                                 |
| `format`      | String(32)         | 课程族：打开方式     | 默认空；`scratch` / `folder` / `ebook`（格式两层论的第一层）                           |
| `publish`     | JSON               | 课程族：发布队列状态 | 入队/构建中/成功/失败（C9/C10）                                                              |
| `created_at`  | String(19)         | 创建时间             |                                                                                              |

唯一约束：`(owner_id, name)` → 老师名下资产名不能重复（D16）。

## 7. `file_order` — 文件树排序

V1 各目录下散落的 `_order.json` 全部收进这一张表（一个文件一份 JSON → 一行记录）。

| 字段            | 类型                | 含义          | 取值 / 备注                           |
| --------------- | ------------------- | ------------- | ------------------------------------- |
| `id`          | Integer · 主键自增 | 行号          |                                       |
| `asset_id`    | String(12) · 索引  | 哪个资产      | →`assets.id`（D16 合表后一列搞定） |
| `parent_path` | String(500)         | 所在目录      | 相对路径；空串 = 根目录               |
| `name`        | String(255)         | 文件/文件夹名 |                                       |
| `position`    | Integer             | 排序位置      | 数字小的排前面                        |

> **单层平铺（D18）**：夹里不再套夹；前端第一版不露文件夹按钮（§3.7），升级路径 = 加 `parent_id` 列。

| 字段         | 类型               | 含义      | 取值 / 备注              |
| ------------ | ------------------ | --------- | ------------------------ |
| `id`       | String(12) · 主键 | 文件夹 id |                          |
| `owner_id` | String(12) · 索引 | 属于谁    | →`accounts.id`        |
| `name`     | String(64)         | 文件夹名  | 如"收件箱""已发送"       |
| `builtin`  | Boolean            | 是否内置  | 内置文件夹不可改名不可删 |

唯一约束：`(owner_id, name)`。

## 12. `class_records` — 课堂记录

同班同日只有一份，**保存即覆盖**（幂等，不产生历史垃圾行）。

| 字段           | 类型                   | 含义         | 取值 / 备注      |
| -------------- | ---------------------- | ------------ | ---------------- |
| `class_id`   | String(12) · 联合主键 | 哪个班       | →`classes.id` |
| `date`       | String(10) · 联合主键 | 哪一天       | `YYYY-MM-DD`   |
| `content`    | Text                   | 当天课堂记录 | 再次保存 = 覆盖  |
| `updated_at` | String(19)             | 最近保存时间 |                  |

## 13. `settings` — 个人界面偏好

一人一行，登录后前端拉取还原界面状态。

| 字段             | 类型               | 含义           | 取值 / 备注                                                  |
| ---------------- | ------------------ | -------------- | ------------------------------------------------------------ |
| `account_id`   | String(12) · 主键 | 属于谁         | →`accounts.id`（一人只有一行）                            |
| `theme`        | String(16)         | 主题           | `''`（橙·默认）/ `green` / `blue` / `custom`（D20） |
| `hue`          | Integer            | 主题色相       | 0-360（默认 95=橙）                                          |
| `font_size`    | Integer            | 字号           | 默认 16                                                      |
| `sidebar`      | Boolean            | 侧边栏是否展开 |                                                              |
| `recent_opens` | JSON（list）       | 最近打开       | 上限`config.RECENT_OPENS_LIMIT`，超了挤掉最旧              |

## 14. `trash` — 统一回收站

A6 停用账号、B5 删班都往这里写一行快照，恢复时照着快照还原。

| 字段           | 类型               | 含义          | 取值 / 备注                                                               |
| -------------- | ------------------ | ------------- | ------------------------------------------------------------------------- |
| `id`         | String(12) · 主键 | 回收站条目 id | 与被删对象的 id 无关（独立生成）                                          |
| `type`       | String(16) · 索引 | 什么类型      | `account` / `class` / `asset`（D16：原 course/resource 并入 asset） |
| `owner_id`   | String(12) · 索引 | 归属人        | 谁删的/本该属于谁；决定谁能看到这条                                       |
| `name`       | String(128)        | 对象名快照    | 回收站列表直接显示，不用回查原表                                          |
| `payload`    | JSON               | 恢复所需快照  | 被删对象的完整字段（如账号的全部信息）                                    |
| `disk_path`  | String(500)        | 磁盘目录      | 内容类被移走的目录；恢复 = 移回来                                         |
| `deleted_at` | String(19)         | 删除时间      |                                                                           |

**边界**：账号条目只可恢复、不提供彻底删；内容类（班级/课程/资料）可由 admin 彻底删除（含磁盘目录）。

## 维护规则

1. **改表必改此文件**：`models.py` 里加/改字段 → 同步本文件对应表格
2. **新表**：加入"总览"表 + 新增一节
3. **阶段推进**：某表从"未来"变为已实现 → 总览表的阶段列打 ✅
